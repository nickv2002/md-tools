# AGENTS.md

Go module `github.com/nickv2002/md-tools` with two CLIs: `mdunwrap` (unwrap hard-wrapped Markdown) and `md2mkdwn` (Markdown to Slack mrkdwn). Shared parsing uses goldmark with the GFM extension.

## Layout

- `cmd/mdunwrap`, `cmd/md2mkdwn`: CLI entry points and their tests.
- `internal/slack/slack.go`: Markdown to mrkdwn converter (`Convert`), including table rendering.
- `internal/unwrap`: unwrapping logic. `internal/cli`: shared `Version` (set by `-ldflags -X` at release).
- `Casks/md-tools.rb`: Homebrew cask, generated by `scripts/render-cask.sh`. Do not hand-edit.
- `scripts/release.sh`: the whole release pipeline. `RELEASING.md`: human description of it.

## Everyday commands

```bash
make check      # gofmt + go vet + go test, identical to CI
make build      # binaries into ./bin
make fuzz       # fuzz the converter, capped at 2 cores and low priority (FUZZTIME=10s, FUZZ_WORKERS=2)
make help
```

## md2mkdwn subprocess contract

The full contract (I/O, exit codes, escaping, link fallback, table rules) lives in `README.md` under "md2mkdwn converter contract". Keep it in sync when behavior changes. Points consumers trip over: pass `-` for stdin that may be empty (bare invocation with empty stdin prints usage, exit 0); output is always LF with exactly one trailing newline; `<` only ever starts a link, so `<!channel>` and friends are inert; links with non-`http(s)/mailto/tel/ftp` schemes, relative paths or a `|` in the label render as `label (url)`. Slack-side facts below were verified in real Slack; the converter itself never touches the network.

## Slack table rendering (learned by testing in real Slack)

- Tables render inside a code fence with padded columns, ` | ` separators and a `---+---` header rule. Keep it ASCII: Unicode box-drawing glyphs (`│ ─ ┼`) come from a fallback font in Slack and their lines do not meet.
- Cells are flattened to plain text (`plainText`) because Slack does not render mrkdwn in code blocks. Links become `label (url)`.
- Width is computed in `displayWidth` per grapheme cluster: CJK and emoji-presentation characters are 2, combining marks and variation selectors are 0, and VS16, skin-tone, keycap, flag and ZWJ sequences collapse to one 2-cell glyph. Slack's fallback fonts draw some of these slightly narrower, so a one-cell wobble on CJK/❌ rows is expected and not fixable here.
- The Slack MCP `slack_send_message` tool takes standard markdown and escapes `&` itself, so `&amp;` looks double-escaped in test DMs. That is a test artifact, not a renderer bug.
- Verified in real Slack (Sep 2026): a zero-width space stops `_` and `~` from opening emphasis but NOT `*` or a backtick, so an escaped `\*` becomes `∗` (U+2217) and an escaped backtick becomes `ˋ`. Bold/italic/strike/code markers inside a `<url|label>` label show up literally, so the converter strips them there. `` ``` `` inside a code block is broken with a zero-width space so nested fences do not close the block.
- Verified in real Slack (Sep 29 2026, hardening pass): grapheme-cluster table widths keep `|` aligned for ZWJ family, skin-tone, flag, VS16 heart and combining-accent rows (only CJK wobbles, as expected); a fenced block containing a zero-width-space-broken nested fence renders as one block; link fallbacks (`label (url)`, relative, `javascript:`) show as plain text while `https:` and `mailto:` links are clickable; `<!channel>` and `<@U123>` never notify. The MCP tool parses its input as standard Markdown, so `*bold*` shows italic, single `~strike~` stays literal and ordered lists renumber oddly around nested lists; those are tool artifacts and cannot validate emphasis mapping.
- Verified in real Slack (Sep 29 2026, loop 2): code-block lines wrap at the window width (about 80 cells at 900px, 120 fits at 1500px), which shreds wide table grids, hence the `DefaultMaxTableWidth` record fallback. In the composer's live formatting, `foo*bar*baz` and `foo_bar_baz` stay literal, `~x~y` strikes fine, a hair space (U+200A) or thin space (U+2009) before the opener makes `*` and `_` format (closing may touch a letter), and a zero-width space or U+2060 does not. The composer drops keystrokes when typing fast, so probe one line at a time and treat it as indicative, not the API's mrkdwn parser.
- Verified non-issues in the composer (Sep 29 2026): stray markers in prose stay literal, so `*args and *kwargs`, `~5 to ~10`, `_private and _other` and `*.go and *.md` need no neutralizing. Slack only formats when the closing marker follows a non-space, so real emphasis already round-trips.
- Quirk, not fixed: through the MCP tool, a nested list under the LAST item of its parent list renders flat (a following sibling item makes nesting work). Unknown whether that is Slack or the tool.
- Resolved through the real API (Sep 29 2026): posting converter output with `chat.postMessage` (`text`, `mrkdwn: true`) renders `&lt;`/`&amp;` inside code correctly as `<` and `&`, `<!channel>`/`<@U123>` stay inert text, and `*bold*`, `_italic_`, `~strike~`, `<url|label>` and the hair-space rule all work. The MCP tool's double-escaping and italic-bold are its own Markdown parsing, not converter bugs. `~x~y` (closing marker touching a letter) does NOT strike in the API, unlike the composer, so strikethrough gets the same hair-space gap as bold and italic.

## Releasing (macOS ARM64 only, on Nick's machine)

Only run when the user asks. Order matters:

1. Commit on `main` (signed commits work unattended when the 1Password agent is unlocked).
2. `git push origin main`, then confirm CI is green: `make ci-status` (or `gh run watch`). Never release on red or pending CI.
3. `make release VERSION=vX.Y.Z` (patch bump from `git describe --tags --abbrev=0`; new user-visible behavior can justify a minor bump).

`make release` runs `make check`, then `scripts/release.sh`, which: cross-builds darwin/arm64, linux/amd64, linux/arm64 with `CGO_ENABLED=0`; signs the Mac binaries with the Developer ID Application identity; notarizes the Mac ZIP with `notarytool` using the App Store Connect API key fetched from 1Password (item "App Store Connect API Key File", vault Private, account nickfam.1password.com; needs interactive approval); verifies the ZIP; generates the `CHANGELOG.md` section and release notes from commit subjects since the previous tag (`scripts/changelog.sh`; write descriptive commit subjects because they become the release description), regenerates and commits the cask and changelog; tags; pushes `main` and the tag; creates and publishes the GitHub release with ZIPs, `checksums.txt`, and `notarization-log.json`.

Requirements: clean `main`, tag must not exist, tools `go zip unzip jq op gh codesign xcrun shasum brew`. Artifacts land in `dist/vX.Y.Z` (gitignored, never overwritten; delete a failed attempt's directory only after confirming nothing was published: `gh release view vX.Y.Z`). The script pushes to `main` itself after committing the cask, so do not add unpushed commits between steps 2 and 3.

After publishing: verify with `gh release view vX.Y.Z`, and do a fresh `brew install` / quarantined-download test as described in `RELEASING.md`.
